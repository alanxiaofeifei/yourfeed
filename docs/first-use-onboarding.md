# First-use onboarding

The tour is optional. RSS reading requires no API key. The home page always offers **Getting started**; resuming or reviewing changes tour position only, never profile, sources or provider configuration. The existing single-source entry remains separate from **Discover & import → Curated**.

## Preview

The non-production preview and its current validation status are recorded in [the project checkpoint](STATUS.md).

## Release configuration

Set `ONBOARDING_AUTO_OFFER_CUTOFF` to the **production launch day**, using the actual approved launch timestamp (ISO 8601 UTC, e.g. `YYYY-MM-DDTHH:mm:ss.sssZ`) **at deploy time**, not a hardcoded or historical date. A disposable non-production preview may deliberately use a past cutoff to exercise new-account invitations; never copy that value into production. Only a trusted local `auth_user.created_at` at or after this cutoff is eligible for an automatic invitation. Existing accounts, identity sources without a trusted creation time, invalid/missing cutoff, corrupt/unknown tour state and read failures fall back to the manual launcher. No member data should be inspected to make this decision. Deploying this PR or enabling the cutoff in production requires separate approval.

Progress is in the current reader instance's D1 `settings` namespace, scoped to authenticated auth mode + account ID + tour version. Neither client-supplied identity nor control/registry storage is used. PATCH requests use revision-based compare-and-swap; a conflict re-reads current state instead of overwriting another tab's dismissal or skips. Ordinary content archives do not copy account progress; the existing full instance backup includes settings and preserves it for same-instance recovery.

## Evidence and privacy

Tour position, viewed/skipped steps, saved configuration and verified reading are distinct. Server-derived evidence uses saved profile rows and source health plus actual content, not an empty default profile, pending sync count or an HTTP 200 alone. AI configuration is not proof of a successful test. A successful connection test can issue an opaque, ten-minute receipt bound to the authenticated account, the physical reader database, its origin, and the exact tested configuration and credential. The receipt stays in the mounted form only and is invalidated on edits. Explicit saving verifies it and atomically stores only its nonce/times and random configuration/credential revisions, not the token, key, key hash or suffix. The tour reports a recently tested connection only while those revisions still match and the absolute receipt expiry has not passed. Changed configuration/credentials, missing/invalid/expired proof, and environment-only credentials remain `not_recorded`; this does not mean a previously working connection has failed. A connection test is a user-initiated potentially billable request, not a guarantee of all AI features or future quota. No automated provider tests, subscriptions, feedback writes, billing upgrades or provider switches are performed by the tour.

The tour uses a small editorial floating popover with automatic side placement and viewport clamping. On mobile it becomes a compact sheet on the opposite side of the target; target scrolling is immediate so placement does not chase a smooth scroll. The React portal remains in the destination's focus scope (including source dialogs), but takes no document-flow space. One persistent pointer-transparent spotlight follows the target with an amber outline, subtle dim and a triangle attached to the popover edge facing the target. Its base is clamped along that edge and its tip aims at the target center. Detached mobile sheets hide the arrow. Geometry is batched per frame on scroll/resize/DOM changes, with ResizeObserver and visualViewport support; there is no polling. Headings receive non-scrolling focus on step changes and translated progress is announced politely. Esc exits; left/right arrows navigate while tour controls have focus, without hijacking text/select inputs. Standard Tab navigation leaves business controls usable. Reduced motion removes geometric transitions, retaining only opacity feedback; the arrow has no independent movement. Original detailed guidance, evidence and chapter navigation remain available behind the translated full-guide disclosure.

Tour progress lives in a child controller, not in the whole feed page; the fixed region is portalled to its destination slot (inside a source dialog when applicable). Next/Back/Skip/Exit respond optimistically without waiting for the network. A background serial queue preserves every action and uses confirmed revisions for CAS; responses rebase server evidence without rewinding newer local steps. Errors discard dependent queued actions and restore confirmed progress with a visible error; conflicts reread the authoritative state rather than replay over another tab. No localStorage progress is introduced. Step PATCH responses already contain evidence, so switching steps does not issue additional GETs. Explicit business saves, refresh and window refocus can reread progress. The home launcher is unconditional, outside empty-feed/profile/completion gates. AccountMenu is the single session-resolution source for the page, so its retry also repairs launcher readiness after a transient session failure; no authentication semantics changed. The top-right **My account** menu is the sole account control, with identity/session actions inside. The bottom-left is a non-interactive privacy/context note directing users there, not a duplicate identity button or an absolute security guarantee. Reading/search instructions can be viewed or skipped; this version does not persist independent proof that a user opened an article or completed a search. Source-readiness evidence is not presented as a personal read-history action.

Tour state does not contain keys or key suffixes, goals, article text, search terms, email addresses or upstream errors. The client does not persist tour progress or key drafts to localStorage. Do not enable session replay or input capture. All browser regression fixtures are synthetic and block non-local browser network requests.

## Optional preference cards (Issue #12)

**Explore your interests** is available beside Getting started, in the empty-feed profile card, in profile settings and above curated source discovery. Ten four-language, two-choice cards balance learning, news and relaxation. Progress is explicit; each question and the entire flow can be skipped. Keyboard 1/2 or left/right selects an answer. Manual entry accepts an interest in the owner's own words, with editable topic choices and an exit to the full profile form.

No provider request occurs on opening. Owners can explicitly customize the questions using their own connection or the default keyless public channel (Issue D). Own connections retain the provider adapter and spending ledger. The five-second server task deadline and six-second client fallback remain; free generation shares the server deadline between OVHcloud and Pollinations, so slower replies use the curated bank. The strict JSON validator requires ten unique IDs and dimensions, bounded plain text, allowed topics and verified, key-free RSS/Atom catalog IDs. Missing credentials, budgets/rate limits, timeouts and malformed output use the curated bank. Generated questions and answers are retained together so cross-device resume uses the same mappings.

The existing D1 `settings` table holds `preference-cards:v1:${userId}`, scoped by the existing authenticated reader and that instance's database, with revision CAS, answers, questions, locale, position, manual text/topics and optional completion time. Reads create no rows. Progress never writes profile or sources. Final review shows interest weights and the exact public feed URLs, permits deselection and marks existing subscriptions. Explicit confirmation saves interests/goals through `PUT /api/profile`, then imports selected feeds through the existing ten-item batch endpoint. Already returned successes and duplicates are retained during retries. Undo on the result screen deletes only IDs actually created by that confirmation; existing subscriptions, profile and answers stay saved. Profile and source writes are separate operations, so a later failure does not roll back an earlier successful save.

The additional feed inspections found valid RSS for Atlas Obscura, ScienceDaily Animals & Nature, GCORES, Lifehacker, BBC World and King Arthur Baking. Solidot returned HTTP 403 in this environment and is not included; Juya/BBC cover the affected choices. Nature/culture feeds are broad matches for pet/cozy-life interests, not dedicated cat/dog feeds. Original articles may have publisher access restrictions even when RSS is public. Fixtures never call live providers or subscribe real instances.

## Providers and billing

Google AI Studio and Groq are the primary free-tier suggestions, subject to account/model/region quotas and terms. NVIDIA development access is supported free, quota/rate limited and does not require a payment method. Groq's [billing FAQ](https://console.groq.com/docs/billing-faqs) distinguishes the Free plan from a paid Developer upgrade.

**A zero estimated rate is not budget protection.** Site estimates, including NVIDIA preset zero rates and user-entered custom rates, cannot prevent an upstream bill. Check provider-side quotas, expiry, billing and available spending limits. This change corrects guidance; it does not change model rates, purchase credits or certify live provider compatibility.

Automatic failure screenshots, traces and video are disabled to avoid capturing credentials. The feedback regression explicitly captures only synthetic, key-free screens to `/workspace/yourfeed-onboarding-20261112/feedback-shots/`. The synthetic harness also exposes numeric React Profiler commit/duration counters; `tour performance benchmark` records five identical step changes, onboarding request counts, long tasks and a 30-resize burst. Set `TOUR_PERF_OUTPUT` to save the numeric JSON; no payloads or inputs are captured. These development-harness timings are directional comparisons, not production/device latency guarantees. Phase A adds a separate [production Worker benchmark](../e2e/PERFORMANCE.md) using the Cloudflare build and local Wrangler, trusted clicks, rAF/performance marks, desktop and CDP-throttled mobile, with labelled native/simulated PATCH latency. Do not compare its numbers with the old development Profiler benchmark. Unit/API tests cover state validation, account/instance isolation, CSRF, CAS conflicts and evidence separately.

Before production approval, manually check VoiceOver/NVDA, real mobile keyboards and 200% zoom, regional signup pages and actual provider/YouTube compatibility with separately authorized test credentials. No live-key test is implied by this PR.

## Default free public AI (Issue D, local candidate)

`server/free-ai.ts` exports `buildFreeAiRequest` for the two fixed official anonymous chat-completions endpoints; it accepts no key and is reusable by an operator's Cloudflare-egress probe. OVHcloud is attempted first, then Pollinations; `json_object`, 4096 output tokens and existing task validators are used. Only visible message content is parsed; reasoning, real free model names, endpoints and raw vendor diagnostics never enter public responses. Responses are capped at 256 KB, redirects blocked, and fetch/body parsing share the timeout. Ordinary explicit tasks have an eight-second total deadline, preference cards five seconds (client six).

Each endpoint reserves a 30-second isolate cooldown before fetching, including in-flight calls; failures open the circuit for at least 30 seconds (normally 60 for HTTP errors), honoring numeric and HTTP-date Retry-After. There are no same-provider retries. Shared Worker egress can still be limited by other tenants. An atomic existing `meta` row caps free attempts at ten tasks per UTC day **per independent single-owner instance**, also bounding every owner's usage; a task can attempt both endpoints. Failed/uncertain tasks consume the reservation; storage failure fails closed. Own-key tasks retain their existing separate spending ledger and never automatically fall back to another service. No schema migration or operator key is added.

Explicit preference cards, source discovery (first three turns), bulk-import assistance, profile advice and single-item reading can use the free channel when no own connection exists. Failure returns curated cards with a visible notice, catalog/manual paths, unchanged ordinary import candidates, or plain reading with a friendly message. Valid article analyses reuse the existing cache. Automatic/bulk/background analysis and connection tests never call free endpoints. Opening a page never requests free AI. Settings expose only availability/mode flags and a generic label; four-language notices explain best effort, public request handling, rates and own-key costs. Restore default changes only the mode, keeps encrypted keys and configuration, and invalidates configuration proof; Save and apply explicitly selects the own connection again.

Box smoke on 2026-11-15: two deliberate synthetic JSON requests returned HTTP 200 (OVH 18.326s, Pollinations 4.483s); both had visible valid JSON and discarded reasoning. An initial existing source-import API unit test lacked a mock after this default changed and made two additional synthetic attempts; mocking was added before further runs. Total outbound attempts: four; no more live tests. These results are not Cloudflare-egress or production acceptance. The five-second preference deadline is deliberately shorter than the observed OVH smoke latency. Official rate-limit reference: [OVHcloud troubleshooting](https://docs.ovhcloud.com/en/guides/public-cloud/ai-machine-learning/ai-endpoints-troubleshooting); previous Pollinations research and terms evidence remain in the task's external `research-D/FINDINGS.md`.
